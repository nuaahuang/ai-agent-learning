# L5-01: 状态机 (State Machine) - Agent生命周期管理

## 一、核心概念

### 1.1 状态机在Agent系统中的作用

状态机是管理Agent生命周期和行为逻辑的核心组件。在多Agent系统中，状态机能够：

- **控制Agent行为模式**：根据不同状态执行不同的处理逻辑
- **管理对话流程**：引导用户交互的状态转换
- **追踪任务执行状态**：监控任务从创建到完成的全生命周期
- **实现工作流引擎**：编排复杂的业务流程

### 1.2 状态机组成要素

| 要素 | 说明 | Agent场景示例 |
|------|------|--------------|
| **状态 (State)** | Agent所处的当前模式或阶段 | idle, running, paused, completed |
| **事件 (Event)** | 触发状态转换的外部或内部信号 | start, pause, resume, complete |
| **动作 (Action)** | 状态转换时执行的操作 | 进入running时记录开始时间 |
| **转换 (Transition)** | 从一个状态到另一个状态的规则 | idle → running (on start) |

### 1.3 状态机类型

1. **有限状态机 (FSM)** - 状态数量有限，适合简单的Agent生命周期管理
2. **分层状态机 (HSM)** - 支持状态嵌套，适合复杂的对话流程
3. **并发状态机** - 多个状态机并行运行，适合多Agent协作场景

## 二、架构设计

### 2.1 状态机接口定义

```python
class State:
    """状态基类 - 定义状态行为接口"""
    
    def on_enter(self, context: dict) -> None:
        """进入状态时执行的初始化操作"""
    
    def on_exit(self, context: dict) -> None:
        """退出状态时执行的清理操作"""
    
    def handle_event(self, event: Event, context: dict) -> Optional['State']:
        """处理事件，返回下一个状态（None表示状态不变）"""
```

## 三、代码实现

### 3.1 核心组件设计

| 组件 | 职责 | 实现要点 |
|------|------|----------|
| **State** | 抽象状态基类 | 定义on_enter, on_exit, handle_event接口 |
| **Event** | 事件封装 | 包含事件类型和附加数据 |
| **StateMachine** | 状态机管理器 | 管理状态转换、历史记录、监听器 |
| **GuardedTransitionStateMachine** | 带守卫条件的状态机 | 支持条件转换 |

### 3.2 在Agent中集成状态机

将状态机集成到Agent类中，实现：
- 任务状态追踪
- 对话流程控制
- 生命周期管理

## 四、实践要点

### 4.1 状态设计原则

1. **单一职责** - 每个状态只负责一种行为模式
2. **状态完整性** - 覆盖所有可能的状态转换
3. **事件驱动** - 通过事件触发转换，而非直接调用
4. **上下文传递** - 通过context共享状态信息

### 4.2 常见模式

- **Guard条件** - 在转换前检查条件（如权限验证）
- **Action执行** - 在转换时执行动作（如记录日志）
- **History状态** - 保存历史状态用于回溯

### 4.3 Agent场景应用

| 应用场景 | 状态设计 | 关键事件 |
|----------|----------|----------|
| 对话机器人 | idle → listening → thinking → responding → idle | user_input, complete, timeout |
| 任务执行Agent | pending → running → completed/error | start, complete, error |
| 协作Agent | waiting → working → reviewing → done | assign, submit, review |

## 五、学习总结

状态机是构建可靠Agent系统的基础组件：

**核心价值**：
- 清晰的状态管理：避免状态混乱和不可预测行为
- 可预测的行为控制：状态转换规则明确
- 易于扩展的架构：新增状态只需实现State接口
- 良好的可维护性：状态逻辑集中管理
