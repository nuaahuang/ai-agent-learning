# L5-03: DAG 调度 (DAG Scheduler)

## 一、核心概念

### 1.1 DAG定义

DAG（Directed Acyclic Graph，有向无环图）是一种用于描述任务依赖关系的数据结构。在Agent系统中，DAG调度器用于：

- **任务编排**：定义任务之间的依赖关系
- **并行执行**：自动识别可并行执行的任务
- **依赖管理**：确保任务按正确顺序执行
- **故障处理**：支持任务失败后的重试和回滚

### 1.2 DAG组成要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **节点 (Node)** | 表示一个任务或操作 | 数据加载、处理、保存 |
| **边 (Edge)** | 表示节点之间的依赖关系 | 任务A完成后才能执行任务B |
| **拓扑排序** | 确定节点的执行顺序 | 按依赖关系排序 |
| **并行度** | 同时执行的最大任务数 | 限制并发执行数量 |

### 1.3 DAG调度策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **拓扑排序执行** | 按依赖顺序依次执行 | 严格依赖的任务链 |
| **动态调度** | 动态检测可执行任务 | 复杂依赖关系 |
| **优先级调度** | 按优先级执行任务 | 有优先级要求的场景 |
| **资源感知调度** | 根据资源状态调整执行 | 资源受限环境 |

## 二、架构设计

### 2.1 DAG调度器架构

```
┌─────────────────────────────────────────────────────────────────┐
│                      DAGScheduler                              │
├─────────────────────────────────────────────────────────────────┤
│  ┌──────────────┐    解析    ┌──────────────┐                │
│  │   DAG定义    │ ─────────→ │  任务图构建   │                │
│  └──────────────┘            └──────┬───────┘                │
│                                     │                          │
│                                     ▼                          │
│  ┌──────────────┐    调度    ┌──────────────┐                │
│  │   执行引擎   │ ←───────── │  任务调度器   │                │
│  └──────────────┘            └──────────────┘                │
│         │                                                      │
│         ▼                                                      │
│  ┌──────────────────────────────────────────┐                  │
│  │  执行模式: 串行 / 并行 / 混合          │                  │
│  └──────────────────────────────────────────┘                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 DAG节点数据结构

```python
@dataclass
class TaskNode:
    task_id: str              # 任务唯一标识
    name: str                 # 任务名称
    func: Callable            # 任务执行函数
    dependencies: List[str]   # 依赖的任务ID列表
    priority: int = 0         # 优先级（数值越大优先级越高）
    max_retries: int = 3      # 最大重试次数
    timeout: Optional[int] = None  # 超时时间（秒）
```

### 2.3 拓扑排序算法

```
Kahn算法（入度表法）:
1. 计算每个节点的入度（依赖数量）
2. 将入度为0的节点加入队列
3. 依次取出节点执行，减少其邻接节点的入度
4. 重复直到队列为空
```

## 三、代码实现

### 3.1 核心组件

| 组件 | 职责 | 实现要点 |
|------|------|----------|
| **TaskNode** | 封装单个任务节点 | 包含任务函数、依赖、优先级 |

| **DAGScheduler** | 执行DAG调度 | 拓扑排序、任务执行、状态管理 |

将DAG调度器与Agent结合，实现：
- 多Agent协作任务编排

## 四、实践要点

### 4.1 DAG设计原则

1. **无环性** - 确保DAG中不存在循环依赖
2. **单一职责** - 每个节点只负责一个任务
3. **可测试性** - 任务函数应易于单元测试
4. **可观察性** - 添加日志和监控

### 4.2 执行模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **串行执行** | 按顺序依次执行 | 任务间有强依赖 |
| **并行执行** | 无依赖任务同时执行 | 计算密集型任务 |
| **混合执行** | 部分并行，部分串行 | 复杂任务编排 |

### 4.3 故障处理策略

- **重试机制**：失败任务自动重试
- **失败传播**：关键任务失败时停止整个DAG
- **降级执行**：部分任务失败时继续执行其他任务
- **状态持久化**：使用Checkpoint保存执行状态
