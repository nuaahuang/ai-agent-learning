# L5-04: Event Bus（事件总线）

## 1. 核心概念

### 1.1 Event Bus 定义

事件总线是一种**发布-订阅模式**的实现，用于解耦系统中各个组件之间的通信。它作为一个中央枢纽，允许组件发布事件而不需要知道谁会接收这些事件，同时允许组件订阅感兴趣的事件而不需要知道谁发布了这些事件。

### 1.2 核心特点

- **解耦性**：发布者和订阅者完全解耦
- **异步通信**：事件可以异步处理
- **可扩展性**：轻松添加新的发布者和订阅者
- **事件溯源**：可以记录和重放事件

### 1.3 组成要素

| 要素 | 说明 |
|------|------|
| **Event** | 事件对象，包含事件类型和数据 |
| **Publisher** | 事件发布者，负责发布事件到总线 |
| **Subscriber** | 事件订阅者，注册感兴趣的事件并处理 |
| **EventBus** | 事件总线核心，负责事件路由和分发 |

### 2.2 核心组件职责

| 组件 | 职责 |
|------|------|
| **Event** | 封装事件数据和元信息 |
| **EventBus** | 管理订阅、发布和分发事件 |
| **EventHandler** | 处理特定类型事件的回调函数 |
| **EventFilter** | 过滤事件，只处理符合条件的事件 |

## 3. 代码实现

### 3.1 Event 类

```python
@dataclass
class Event:
    event_id: str           # 事件唯一标识
    event_type: str         # 事件类型
    data: Dict[str, Any]    # 事件数据
    timestamp: float        # 事件时间戳
    source: str             # 事件来源
```

### 3.2 EventBus 类

核心功能：
- `subscribe(event_type, handler)` - 订阅事件
- `unsubscribe(event_type, handler)` - 取消订阅
- `publish(event)` - 发布事件
- `dispatch(event)` - 分发事件

### 3.3 设计模式

- **观察者模式**：订阅者监听事件变化
- **中介者模式**：EventBus作为中介协调通信
- **策略模式**：支持不同的事件分发策略

---

## 4. 应用场景

### 4.1 Agent 通信

不同Agent之间通过事件总线进行通信，无需直接依赖。

### 4.2 状态同步

当某个Agent状态变化时，发布事件通知其他相关Agent。

### 4.3 日志和监控

订阅系统事件进行日志记录和监控告警。

### 4.4 工作流协调

通过事件驱动工作流的各个阶段。

---

## 5. 关键特性

### 5.1 异步处理

支持异步事件处理，避免阻塞主线程。

### 5.2 事件过滤

支持基于条件过滤事件，只处理感兴趣的事件。

### 5.3 错误处理

事件处理异常不会影响其他事件处理。

### 5.4 事件优先级

支持事件优先级，高优先级事件优先处理。

---

## 6. 实践要点

### 6.1 事件命名规范

使用清晰的事件类型命名，如 `agent.created`, `task.completed`。

### 6.2 事件数据结构

保持事件数据简洁，只包含必要信息。

### 6.3 订阅管理

及时清理不再需要的订阅，避免内存泄漏。

### 6.4 错误隔离

每个事件处理器应该独立处理异常，避免影响其他处理器。

---

## 7. 总结

Event Bus 是构建松耦合、可扩展Agent系统的关键组件。它通过发布-订阅模式实现了组件之间的解耦，使得系统更加灵活和易于维护。
