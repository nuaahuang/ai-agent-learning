# L6-02: Rate Limiter（请求限流）

## 1. 核心概念

### 1.1 Rate Limiter 定义

请求限流是指对系统的请求速率进行控制，防止系统过载：

- **保护系统**：防止过多请求导致服务崩溃
- **公平性**：确保所有用户公平使用资源
- **流量整形**：平滑突发流量
- **API保护**：防止恶意攻击

### 1.2 限流算法对比

| 算法 | 特点 | 适用场景 |
|------|------|---------|
| **固定窗口计数器** | 简单，可能出现边界问题 | 低精度场景 |
| **滑动窗口计数器** | 精确，内存占用较大 | 需要精确控制 |
| **令牌桶** | 平滑输出，支持突发 | 大多数场景 |
| **漏桶** | 严格限流，平滑输出 | 流量整形 |

## 2. 算法详解

### 2.1 令牌桶算法

```
┌─────────────────────────────────────┐
│         令牌桶                      │
│  ┌─────────────────────────────┐   │
│  │ 令牌存储区                   │   │
│  │  capacity = 100            │   │
│  │  current = 60              │   │
│  └─────────────────────────────┘   │
│         │        │                 │
│         ▼        ▼                 │
│   每秒添加令牌    请求消耗令牌       │
│   (rate = 10/s)  (成功或等待)      │
└─────────────────────────────────────┘
```

**核心逻辑**：
1. 按固定速率向桶中添加令牌
2. 请求到达时消耗令牌
3. 令牌不足时等待或拒绝

### 2.2 滑动窗口计数器

```
时间轴 →
┌──────────────────────────────────────────────────┐
│  旧窗口  │←─────── 滑动窗口 ───────→│  新数据  │
│  [已丢弃] │  [最近1秒的请求]         │  [即将进入]│
└──────────────────────────────────────────────────┘
```

**核心逻辑**：
1. 维护一个固定大小的时间窗口
2. 新请求加入窗口尾部
3. 旧请求从窗口头部移除
4. 窗口满时拒绝新请求

## 4. 核心功能

### 4.1 限流策略

| 策略 | 说明 | 示例 |
|------|------|------|
| **全局限流** | 整个系统的请求上限 | 每秒100次 |
| **用户限流** | 每个用户的请求上限 | 每用户每秒10次 |
| **IP限流** | 每个IP的请求上限 | 每IP每秒50次 |
| **资源限流** | 特定资源的请求上限 | 某API每秒20次 |

### 4.2 限流模式

| 模式 | 说明 |
|------|------|
| **拒绝模式** | 超过限制直接拒绝 |
| **等待模式** | 超过限制等待令牌 |
| **降级模式** | 超过限制返回降级结果 |

## 5. 实践要点

### 5.1 分布式限流

在分布式场景下，需要使用共享存储（如Redis）：

- Redis + Lua脚本实现原子操作
- 使用Redis的INCR和EXPIRE命令
- 使用Redis的滑动窗口实现

### 5.2 熔断与限流的区别

| 对比维度 | 限流 (Rate Limiting) | 熔断 (Circuit Breaker) |
|---------|---------------------|----------------------|
| **目的** | 控制请求速率 | 保护下游服务 |
| **触发条件** | 请求频率过高 | 错误率过高 |
| **行为** | 拒绝/等待请求 | 快速失败 |
| **恢复方式** | 自动恢复 | 半开状态测试 |

---

## 6. 总结

请求限流是规模化部署的必备能力：
- 保护系统稳定性
- 保证服务公平性
- 防止恶意攻击
- 平滑流量峰值
