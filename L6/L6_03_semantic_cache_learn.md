# L6-03: Semantic Cache（语义缓存）

## 1. 核心概念

### 1.1 语义缓存定义

语义缓存是一种基于语义相似性的缓存机制，它不是简单地比较请求是否完全相同，而是比较请求的语义含义是否相似：

- **传统缓存**：完全匹配才能命中
- **语义缓存**：语义相似即可命中

### 1.2 为什么需要语义缓存

| 场景 | 传统缓存 | 语义缓存 |
|------|---------|---------|
| 相同问题不同表述 | 未命中 | 命中 |
| 相似问题 | 未命中 | 命中 |
| 同义词替换 | 未命中 | 命中 |

### 1.3 应用价值

- **节省成本**：减少重复的LLM调用
- **提升响应速度**：缓存响应比LLM调用快得多
- **提高一致性**：相似问题返回相似答案

## 3. 核心功能

### 3.1 语义相似度计算

| 算法 | 说明 | 适用场景 |
|------|------|---------|
| **Cosine Similarity** | 余弦相似度 | 常用，效果好 |
| **Euclidean Distance** | 欧氏距离 | 需要归一化 |
| **Dot Product** | 点积 | 未归一化向量 |

### 3.2 缓存策略

| 策略 | 说明 |
|------|------|
| **FIFO** | 先进先出 |
| **LRU** | 最近最少使用 |
| **LFU** | 最不经常使用 |
| **TTL** | 时间过期 |

### 3.3 缓存条目结构

```python
{
    "question": "原始问题",
    "embedding": [0.1, 0.2, ...],  # 向量表示
    "answer": "缓存的答案",
    "usage": {"prompt_tokens": 100, "completion_tokens": 200},
    "timestamp": 1699999999,
    "hit_count": 5,
    "ttl": 3600
}
```

## 4. 关键指标

### 4.1 命中率

```
命中率 = 缓存命中次数 / 总请求次数 × 100%
```

### 4.2 缓存有效性

- **精确命中率**：完全匹配命中
- **语义命中率**：相似匹配命中
- **总体命中率**：(精确命中 + 语义命中) / 总请求

## 5. 实践要点

### 5.1 Embedding 模型选择

| 模型 | 特点 |
|------|------|
| **text-embedding-ada-002** | OpenAI，效果好 |
| **all-MiniLM-L6-v2** | 开源，轻量级 |
| **bge-small-en** | 中文支持好 |

### 5.2 相似度阈值

- **高阈值**（0.9+）：严格匹配，准确率高，命中率低
- **中阈值**（0.7-0.9）：平衡准确率和命中率
- **低阈值**（0.5-0.7）：宽松匹配，命中率高，可能有错误

### 5.3 缓存更新策略

- **定期刷新**：按时间周期更新
- **按需更新**：检测到数据变化时更新
- **被动失效**：TTL过期自动失效

---

## 6. 总结

语义缓存是提升LLM应用性能的关键技术：
- 基于语义相似性匹配，提高缓存命中率
- 显著降低API调用成本
- 提升响应速度，改善用户体验
- 需要权衡命中率和准确率
