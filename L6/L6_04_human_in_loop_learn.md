# L6-04: Human-in-the-Loop（人工介入）

## 1. 核心概念

### 1.1 人工介入定义

Human-in-the-Loop（HITL）是指在 Agent 自动化流程中，针对高风险、高不确定性的决策点引入人工审核与确认的机制：

- **自动化为主**：大部分任务由 Agent 自动完成
- **关键点人工**：高风险操作需要人工确认
- **闭环反馈**：人工决策可反哺 Agent 学习

### 1.2 为什么需要人工介入

| 场景 | 风险 | 人工介入价值 |
|------|------|------------|
| 资金交易 | 资损 | 防止错误转账 |
| 删除操作 | 数据丢失 | 二次确认 |
| 对外发送 | 声誉风险 | 内容审核 |
| 低置信度决策 | 决策错误 | 人工判断 |

### 1.3 介入触发条件

| 触发类型 | 说明 |
|---------|------|
| **置信度阈值** | Agent 置信度低于阈值时介入 |
| **风险等级** | 高风险操作强制介入 |
| **规则匹配** | 命中敏感规则时介入 |
| **金额阈值** | 超过金额限制时介入 |

## 3. 核心功能

### 3.1 审批状态

| 状态 | 说明 |
|------|------|
| **PENDING** | 等待审批 |
| **APPROVED** | 已批准 |
| **REJECTED** | 已拒绝 |
| **TIMEOUT** | 审批超时 |
| **AUTO_APPROVED** | 自动批准（低风险） |

### 3.2 风险等级

| 等级 | 说明 | 处理方式 |
|------|------|---------|
| **LOW** | 低风险 | 自动执行 |
| **MEDIUM** | 中风险 | 记录日志 |
| **HIGH** | 高风险 | 人工审批 |
| **CRITICAL** | 极高风险 | 多人审批 |

## 4. 介入模式

### 4.1 阻塞式介入

Agent 暂停执行，等待人工决策后继续：

```
Agent → 暂停 → 等待审批 → 人工决策 → 恢复执行
```

### 4.2 异步式介入

Agent 提交审批请求后继续其他任务，审批完成后回调：

```
Agent → 提交审批 → 继续其他任务
              ↓
         人工决策 → 回调通知 → 执行操作
```

### 4.3 检查点介入

结合 Checkpoint 机制，在审批点保存状态，可随时恢复：

```
Agent → 保存检查点 → 等待审批 → 从检查点恢复
```

## 5. 实践要点

### 5.1 超时处理

- **默认拒绝**：超时后默认拒绝，确保安全
- **默认批准**：低风险场景超时后批准
- **升级处理**：超时后升级给更高级别审批

### 5.2 审批人分配

| 策略 | 说明 |
|------|------|
| **轮询分配** | 平均分配给审批人 |
| **角色分配** | 按风险等级分配给不同角色 |
| **负载均衡** | 分配给最空闲的审批人 |

### 5.3 与 Agent 集成

- Agent 调用工具前进行风险评估
- 高风险工具自动触发审批流程
- 审批通过后才允许执行

---

## 6. 总结

人工介入是保障 Agent 安全运行的关键机制：
- 在自动化与安全之间取得平衡
- 针对高风险操作引入人工审核
- 支持阻塞式、异步式、检查点等多种介入模式
- 通过超时处理保障流程不会卡死
