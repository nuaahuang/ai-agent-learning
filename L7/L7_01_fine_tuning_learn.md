# L7-01: Fine-tuning（模型微调）

## 1. 核心概念

### 1.1 什么是 Fine-tuning

Fine-tuning（微调）是在预训练大模型的基础上，使用特定领域的数据进行二次训练，让模型适应特定任务或领域：

- **预训练模型**：在海量通用数据上训练，具备通用能力
- **微调**：用少量领域数据调整模型参数，强化特定能力

### 1.2 为什么 Agent 需要微调

| 场景 | Prompt工程 | 微调 |
|------|-----------|------|
| 固定格式输出 | 每次都要写示例 | 学会后无需示例 |
| 领域术语理解 | 上下文塞知识 | 内化到参数 |
| 特定风格/语气 | 难以稳定 | 稳定输出 |
| 降低推理成本 | 长prompt费token | 短prompt即可 |
| 工具调用准确性 | 靠提示约束 | 训练强化 |

### 1.3 微调 vs 其他方案

| 方案 | 适用场景 | 成本 |
|------|---------|------|
| **Prompt工程** | 快速验证、通用任务 | 低 |
| **RAG检索增强** | 知识频繁更新 | 中 |
| **Fine-tuning** | 固定能力、风格、格式 | 高 |
| **预训练** | 全新领域基座 | 极高 |

**经验法则**：先 Prompt → 再 RAG → 最后才考虑微调。微调不是首选，是优化手段。

## 2. 微调方法

### 2.1 全参数微调 vs 高效微调

| 方法 | 说明 | 显存需求 | 适用 |
|------|------|---------|------|
| **Full Fine-tuning** | 更新全部参数 | 极高 | 资源充足 |
| **LoRA** | 训练低秩适配矩阵 | 低 | 主流方案 |
| **QLoRA** | 量化+LoRA | 极低 | 消费级GPU |
| **Prefix Tuning** | 只训练前缀向量 | 低 | 轻量任务 |
| **Adapter** | 插入小型适配层 | 低 | 多任务切换 |

### 2.2 LoRA 原理

```
原始权重 W (冻结)  +  低秩分解 ΔW = B × A (可训练)
   [d×d]                      [d×r] × [r×d]   (r << d)

最终: h = Wx + BAx
```

核心思想：冻结原模型，只训练两个小矩阵 A、B，大幅减少可训练参数（可降99%+）。

### 2.3 微调类型

| 类型 | 说明 |
|------|------|
| **SFT（监督微调）** | 用"输入-输出"对训练 |
| **DPO（直接偏好优化）** | 用"好答案-坏答案"对训练 |
| **RLHF（人类反馈强化学习）** | 奖励模型+强化学习 |

## 3. 微调全流程

### 3.1 标准流程

```
① 数据准备 → ② 数据格式化 → ③ 训练配置 → ④ 训练 → ⑤ 评估 → ⑥ 部署
```

### 3.2 数据准备（最关键）

> 微调效果 80% 取决于数据质量。

| 要点 | 说明 |
|------|------|
| **数据质量 > 数量** | 几百条高质量胜过几万条噪声 |
| **多样性** | 覆盖各种场景和边界 |
| **一致性** | 格式、风格统一 |
| **去噪** | 剔除错误、重复、低质样本 |

### 3.3 数据格式（对话格式示例）

```json
{
  "messages": [
    {"role": "system", "content": "你是金融分析助手"},
    {"role": "user", "content": "分析这只股票的财报"},
    {"role": "assistant", "content": "根据财报数据..."}
  ]
}
```

### 3.4 关键超参数

| 参数 | 说明 | 经验值 |
|------|------|--------|
| **learning_rate** | 学习率 | 1e-4 ~ 5e-5 |
| **epochs** | 训练轮数 | 1~3（防过拟合） |
| **batch_size** | 批大小 | 看显存 |
| **lora_rank** | LoRA秩 | 8~64 |
| **warmup_steps** | 预热步数 | 总步数的5%~10% |

## 4. 评估

### 4.1 评估维度

| 维度 | 指标 |
|------|------|
| **训练指标** | loss、perplexity |
| **任务指标** | 准确率、F1、BLEU、ROUGE |
| **人工评估** | 有用性、安全性、风格符合度 |
| **对比评估** | 与基线模型A/B对比 |

### 4.2 常见问题

| 问题 | 表现 | 解决 |
|------|------|------|
| **过拟合** | 训练好、测试差 | 减少epochs、增加数据 |
| **灾难性遗忘** | 通用能力下降 | 混入通用数据、降低学习率 |
| **欠拟合** | 都不好 | 增加epochs、调高学习率 |

## 5. Agent 场景的微调实践

### 5.1 典型场景

| 场景 | 微调目标 |
|------|---------|
| **工具调用** | 提升 function calling 准确率和格式稳定性 |
| **领域问答** | 内化领域知识和术语 |
| **结构化输出** | 稳定输出JSON/特定格式 |
| **角色风格** | 固定语气、人设 |

### 5.2 数据从哪来

- **人工标注**：质量最高，成本高
- **线上日志**：真实交互数据，需脱敏清洗
- **大模型蒸馏**：用GPT-4等生成训练数据
- **规则合成**：模板批量生成

### 5.3 工程注意事项

- **数据脱敏**：训练数据可能含隐私（结合L6-05护栏）
- **版本管理**：数据集、模型、配置都要版本化
- **可回滚**：保留基线模型，效果差能回退
- **持续迭代**：收集新数据持续优化

---

## 6. 总结

Fine-tuning 是 Agent 能力深化的重要手段：
- 不是首选方案，优先 Prompt 和 RAG
- 数据质量是成败关键（80%）
- LoRA/QLoRA 是当前主流高效微调方法
- 全流程：数据准备→格式化→训练→评估→部署
- Agent 场景常用于工具调用、领域问答、结构化输出优化
