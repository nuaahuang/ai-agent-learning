# L7-02: 多模态 Agent（Multimodal Agent）

## 1. 核心概念

### 1.1 什么是多模态 Agent

多模态 Agent 是能够理解和处理多种数据模态（文本、图像、音频、视频）的智能体：

- **单模态**：只处理文本
- **多模态**：同时理解文本、图像、音频、视频等

### 1.2 常见模态

| 模态 | 输入示例 | 典型任务 |
|------|---------|---------|
| **文本** | 文字、文档 | 问答、生成 |
| **图像** | 照片、图表、截图 | 识别、描述、OCR |
| **音频** | 语音、音乐 | 转写、识别、合成 |
| **视频** | 视频流 | 理解、摘要、检测 |

### 1.3 多模态的价值

| 场景 | 单模态局限 | 多模态优势 |
|------|-----------|-----------|
| 看图问答 | 无法理解图片 | 直接分析图像 |
| 语音助手 | 需先转文字 | 端到端理解 |
| 文档处理 | 丢失版式/图表 | 理解完整文档 |
| 视频分析 | 无法处理 | 时序+画面理解 |

## 2. 架构设计

### 2.1 多模态 Agent 架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                     Multimodal Agent                             │
│                                                                  │
│   文本 ──┐                                                       │
│   图像 ──┤    ┌──────────────┐    ┌──────────────┐               │
│   音频 ──┼──→ │  模态编码器   │ ─→ │  统一表示     │               │
│   视频 ──┘    │  Encoders    │    │  (Embedding) │               │
│              └──────────────┘    └──────┬───────┘               │
│                                         │                       │
│                                         ▼                       │
│                                  ┌──────────────┐               │
│                                  │  多模态LLM    │               │
│                                  │  推理/融合    │               │
│                                  └──────┬───────┘               │
│                                         │                       │
│                                         ▼                       │
│                                  文本/图像/语音输出              │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 模态融合策略

| 策略 | 说明 | 特点 |
|------|------|------|
| **早期融合** | 输入层就融合各模态 | 交互充分，计算大 |
| **晚期融合** | 各自处理后融合结果 | 灵活，交互弱 |
| **混合融合** | 多层次融合 | 平衡 |
| **交叉注意力** | 模态间注意力交互 | 主流方案 |

## 6. 深入主题（进阶）

### 6.1 各模态编码器（编码器本身就是模型）

编码器是预训练好的神经网络，负责把某模态转成特征向量，通常**冻结不参与微调**。

**视觉编码器**：

| 编码器 | 架构 | 参数量 | 用在哪 |
|--------|------|--------|--------|
| CLIP ViT-L/14 | Vision Transformer | 428M | LLaVA、早期GPT-4V（最经典） |
| SigLIP / SigLIP2 | ViT变体（对齐更优） | - | 较新方案，OCR强 |
| EVA-CLIP | 增强版CLIP | - | 高性能场景 |

> 工作原理：图像切成 14×14 patch，每块转成向量，整图变成 patch token 序列（如256个token）。

**音频编码器**：Whisper Encoder（最常用）、Wav2Vec 2.0、CLAP（音频版CLIP）
**文本编码器**：LLM 自带 Embedding 层（BERT、LLaMA token embedding）
**视频编码器**：图像编码器 + 时序建模（抽关键帧用CLIP编码 + 时序注意力）

> 关键：编码器通常**冻结**。CLIP 已在4亿图文对上学会提取视觉特征，重训反而破坏能力（实验：Frozen CLIP 33.0% 反超 fine-tuned CLIP 32.3%）。

### 6.2 跨模态对齐：两个层面

**层面一：语义对齐 —— 靠 CLIP 这类对比学习模型**

CLIP 用 4亿对(图片,文字) 对比学习训练：让"狗的图片"向量和"狗"文字向量靠近，不匹配的远离。训练后视觉特征天然与文本语义对齐，这是对齐的根基。

**层面二：空间对齐 —— 靠投影层（Projector）**

CLIP 输出维度（如1024）和 LLM 词嵌入维度（如1536）不同，需投影层桥接：

```
CLIP视觉特征 [256,1024] → 投影层Projector(2层MLP,可训练) → [256,1536] → 塞进LLM
```

```python
class VisionProjector(nn.Module):
    def __init__(self, vision_dim, language_dim):
        self.fc1 = nn.Linear(vision_dim, hidden_dim)   # 1024 → 中间层
        self.act = nn.GELU()
        self.fc2 = nn.Linear(hidden_dim, language_dim) # 中间层 → 1536
```

> 分工：CLIP（冻结）做语义对齐，投影层（可训练，约6M参数）做维度对齐。训练只训投影层+LoRA。

### 6.3 三代多模态架构演进

| 代际 | 范式 | 融合方式 | 代表模型 |
|------|------|---------|---------|
| 第一代 | 拼接式(Pipeline) | 投影层桥接，融合弱 | BLIP-2、MiniGPT-4 |
| 第二代 | 指令微调式 | LLM多模态指令微调 | LLaVA 1.5、Qwen-VL、InstructBLIP |
| 第三代 | 原生统一 | 表征空间层面对齐 | GPT-4o、Gemini 2.5、GPT-6 |

**第一代拼接式流程**：
```
图像 → 视觉编码器(冻结) → 投影层 → LLM → 输出文本
```
局限：图像信息压缩丢失细节、只能输出文本、扩展新模态需重设计投影层。

### 6.4 原生统一多模态（GPT-4o范式）原理

核心思想：**一切皆 Token**——文本/图像/音频全转成同格式token，拼成长序列喂给同一个Transformer，中间不经过"转文字"，避免信息损失。

```
拼接式: 语音→[Whisper]→文字→[LLM]→文字→[TTS]→语音  (文字瓶颈丢失90%语气)
原生式: 语音+图像→[统一编码]→混合token→[同一LLM]→混合token→[解码]→语音+文字
```

**(1) 统一编码**：各模态转token，但都投影成**相同维度**向量
- 文本：BPE分词（GPT-4o用o200k_base，约20万词表）
- 图像：ViT切patch，一张图约197个视觉token（分辨率越高token越多越费钱）
- 音频：每25ms帧提128维log-mel特征，投影到对齐空间（连续嵌入保留语气情感）

**(2) 统一表征空间**：靠**端到端联合训练**让所有模态从零长在同一空间
- 所有模态token投影成相同维度（如4096），数据结构一致，Transformer分不清也不需分清
- 从预训练第一天就在文本+图像+音频混合数据上训练，**共享同一套参数**
- 统一表征空间是训练"涌现"的结果，非后期加对齐层硬接

**(3) 统一处理**：混合序列进同一Transformer，**共享自注意力**实现跨模态融合
```
[文本t1][文本t2][图像p1][图像p2][音频a1]...
  所有token在同一注意力矩阵互相计算
  文本token可关注图像token边缘，音频token可参考文本语义
```

**原生式 vs 拼接式对比**：

| | 拼接式(LLaVA) | 原生式(GPT-4o) |
|---|---------------|-----------------|
| 编码器 | 独立CLIP(冻结) | 学习到的统一tokenizer |
| 对齐 | 后期加投影层桥接 | 联合训练天然长在一起 |
| 训练 | 分阶段，LLM后期微调 | 端到端从头联合训练 |
| 表征空间 | 两个空间靠投影层连接 | 一个空间，原生统一 |

### 6.5 融合核心技术：交叉注意力（Cross-Attention）

无论哪种架构，融合关键机制都是交叉注意力：
> **Query 来自文本特征，Key/Value 来自投影后的视觉特征**

```
文本(Query)"这个报错" ──查询──→ 图像(Key/Value)各区域
                                     │
                          注意力权重高的是"红色错误文字区域"
```
这让"这个报错"能聚焦到图中错误文字区域，而非平均看整张图。

## 7. 总结

多模态 Agent 是 Agent 能力扩展的重要方向：
- 突破纯文本限制，理解图像、音频、视频
- 核心是模态编码 + 统一表示 + 融合推理
- 交叉注意力是主流融合方案
- 工程上需关注预处理、token成本、路由分发
- Agent 场景常见于截图问答、语音对话、文档分析
