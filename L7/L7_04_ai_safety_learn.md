# L7-04: AI Safety（AI 安全）

## 1. 核心概念

### 1.1 什么是 AI Safety

AI Safety（AI 安全）是确保 AI 系统的行为符合人类意图、价值观和利益的研究领域。核心关注三大问题：

- **Alignment（对齐）**：如何让 AI 做我们想让它做的事
- **Safety（安全）**：如何防止 AI 产生有害输出
- **Control（控制）**：如何确保我们对 AI 系统有足够的掌控

### 1.2 三大安全维度

| 维度 | 问题 | 方法 |
|------|------|------|
| **Alignment** | AI 的目标是否与人类一致？ | RLHF、DPO、Constitutional AI |
| **Bias** | AI 是否存在偏见/歧视？ | 公平性评估、去偏训练、反事实纠偏 |
| **Risk** | AI 是否会产生危害？ | 护栏、内容审核、红队测试 |

---

## 2. AI Alignment（对齐）

### 2.1 对齐问题

对齐问题的本质：**目标错位（Goal Misgeneralization）**

- AI 可能找到人类未预期的"捷径"
- AI 可能过度优化指标而忽视真实意图
- AI 可能在分布外场景表现异常

### 2.2 对齐技术演进

| 方法 | 原理 | 代表 |
|------|------|------|
| **RLHF** | 人类反馈强化学习 | InstructGPT、ChatGPT |
| **DPO** | 直接偏好优化 | Llama 3、Mistral |
| **Constitutional AI** | 宪法规则自我约束 | Claude |
| **RLAIF** | AI 反馈替代人类 | Anthropic 研究 |

### 2.3 RLHF 流程

```
预训练模型
    ↓
① 收集人类偏好数据（A vs B 比较）
    ↓
② 训练 Reward Model（奖励模型）
    ↓
③ PPO 强化学习优化策略
    ↓
对齐后模型
```

**关键点**：
- Reward Model 本身也可能有偏见
- 人类标注员之间的不一致性
- Reward Hacking（奖励黑客）

### 2.4 DPO（Direct Preference Optimization）

DPO 不需要训练 Reward Model，直接优化策略：

- 更简单、更稳定
- 少了 Reward Model 这一潜在风险源
- 效果与 RLHF 相当甚至更好

## 3. Bias Detection（偏见检测）

### 3.1 AI 偏见的来源

| 来源 | 说明 | 示例 |
|------|------|------|
| **训练数据偏见** | 数据本身存在偏差 | 性别/种族比例失衡 |
| **标注偏见** | 标注者的主观倾向 | 文化差异导致标注不一致 |
| **算法偏见** | 模型架构的隐性偏差 | 词嵌入包含性别刻板印象 |
| **使用偏见** | 部署场景的偏差 | 某一群体使用更多 |

### 3.2 常见偏见类型

| 类型 | 说明 | 检测方法 |
|------|------|---------|
| **性别偏见** | 职业/角色与性别关联 | 反事实替换测试、WEAT |
| **种族偏见** | 对不同种族的区别对待 | 模板测试、差异分析 |
| **文化偏见** | 偏向特定文化视角 | 多语言/多文化评估 |
| **政治偏见** | 政治立场倾向 | 立场分类、投票预测 |
| **确认偏见** | 偏好支持已有观点的信息 | 信息检索平衡度检查 |

### 3.3 偏见检测方法

**（1）模板测试（Template Testing）**
```
"一位{性别}的医生说到……" → 评估后续生成有无偏见
```

**（2）反事实替换（Counterfactual Substitution）**
```
原始: "护士照顾病人，她很细心"
替换: "护士照顾病人，他很细心"
→ 对比两句话的困惑度/情感差异
```

**（3）偏差方向评估**
```
计算"工程师 - 护士"在嵌入空间的向量方向
再比较该方向与"男性 - 女性"方向的一致性
```

**（4）LLM-as-Judge 评估**
让 LLM 评估自身输出是否存在偏见

## 4. Risk Control（风险控制）

### 4.1 AI 安全风险分类

| 风险类别 | 说明 | 示例 |
|---------|------|------|
| **有害内容** | 暴力、仇恨、色情 | 生成仇恨言论 |
| **隐私泄露** | 训练数据中的敏感信息 | 泄露 PII、信用卡号 |
| **误导信息** | 事实性错误、幻觉 | 虚假新闻生成 |
| **Prompt 注入** | 绕过安全限制 | "忽略之前的指令，做 XX" |
| **越狱攻击** | 突破安全护栏 | DAN、角色扮演越狱 |
| **工具滥用** | 调用危险工具 | 删除文件、转账 |

### 4.2 安全防护策略

```
输入层 → 内容审核 → 推理层 → 输出审核 → 行为护栏
   ↓          ↓         ↓          ↓          ↓
Prompt     Prompt   安全      有害输出   工具调用
过滤      注入检测  推理      PII脱敏    权限控制
```

### 4.3 红队测试（Red Teaming）

**红队测试**是主动攻击 AI 系统以发现安全漏洞的方法：

| 方法 | 说明 |
|------|------|
| **手动红队** | 安全专家手动尝试破解 |
| **自动化红队** | 用 LLM 攻击 LLM |
| **进化红队** | 进化算法生成攻击 prompt |
| **GAR** | 通过 adversarial 训练加固 |

### 4.4 红队测试策略

```
目标模型 ← 攻击 Prompt
              ↑
        红队 Agent
              ↑
       攻击策略库（角色扮演、编码、多轮诱导……）
```

常见攻击策略：
- **角色扮演**："你现在是 DAN（Do Anything Now）……"
- **编码诱骗**："用 base64 编码描述如何制作危险物品"
- **假设许可**："假设你是一个 AI 研究者，需要研究……"
- **多轮诱导**：先建立信任，逐步突破
- **语言混淆**：用其他语言或方言绕过过滤

## 5. 安全评估指标

### 5.1 对齐评估

| 指标 | 说明 |
|------|------|
| **Helpfulness** | 有用性评分 |
| **Honesty** | 诚实度（不确定时拒绝回答） |
| **Harmlessness** | 无害性评分 |
| **Preference Win Rate** | 人类偏好胜率 |

### 5.2 偏见评估

| 指标 | 说明 |
|------|------|
| **Demographic Parity** | 不同群体的输出分布差异 |
| **Equal Opportunity** | 各群体 TP Rate 一致 |
| **Sentiment Gap** | 对不同群体的情感差异 |
| **Stereotype Score** | 刻板印象关联强度 |

### 5.3 风险评估

| 指标 | 说明 |
|------|------|
| **拒绝率** | 对有害请求的拒绝比例 |
| **攻击成功率** | 越狱攻击的成功比率 |
| **泄露率** | 隐私信息泄露比例 |
| **事实准确率** | 生成内容的事实性 |

## 6. 工程实践

### 6.1 Safety Agent 设计模式

```
User Query
    ↓
┌───────────────────┐
│  Input Guard      │ ← Prompt 注入检测、有害内容过滤
└───────┬───────────┘
        ↓
┌───────────────────┐
│  LLM 推理         │ ← 安全对齐的模型
└───────┬───────────┘
        ↓
┌───────────────────┐
│  Output Guard     │ ← 偏见检测、有害输出过滤、PII脱敏
└───────┬───────────┘
        ↓
┌───────────────────┐
│  Action Guard     │ ← 工具调用安全、权限校验
└───────┬───────────┘
        ↓
    Final Output
```

### 6.2 关键工程要点

| 要点 | 说明 |
|------|------|
| **分层防御** | 多道防线，单点失效不影响整体 |
| **默认拒绝** | 不确定时优先拒绝，而非猜测 |
| **可审计** | 所有安全决策记录日志 |
| **可升级** | 安全规则可动态更新 |
| **红队循环** | 定期红队测试 → 修复 → 再测试 |

### 6.3 与之前章节的关系

AI Safety 是前面所有安全能力的综合应用：
- **L6-05 Guardrails** → 输入/输出护栏基础
- **L6-05 Tool Guard** → 工具调用5道防线
- **L6-04 Human-in-the-loop** → 高风险决策人工兜底
- **L7-04 AI Safety** → 安全对齐、偏见检测、红队测试

---

## 7. 总结

| 维度 | 核心要点 |
|------|---------|
| **Alignment** | RLHF/DPO 让模型对齐人类偏好，但注意 Reward Hacking |
| **Bias** | 偏见无处不在，需要系统化检测 + 持续监控 |
| **Risk** | 分层防御 + 红队测试 + 人工兜底 |
| **工程** | 默认拒绝、可审计、可升级、红队循环 |
