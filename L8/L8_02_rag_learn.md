# L8-02: RAG 知识库与检索（Retrieval-Augmented Generation）

## 1. 核心概念

### 1.1 什么是 RAG

RAG（检索增强生成）= 检索（Retrieval）+ 生成（Generation）。在大模型生成回答前，先从外部知识库检索相关信息，作为上下文注入：

```
用户问题 → 检索知识库 → 相关文档 + 问题 → LLM → 基于检索内容生成回答
```

### 1.2 为什么需要 RAG

| 大模型局限 | RAG 解决 |
|-----------|---------|
| 知识有截止日期 | 检索最新知识 |
| 不知道私有数据 | 检索企业内部知识 |
| 会"幻觉"编造 | 基于真实文档作答 |
| 无法溯源 | 给出引用来源 |

### 1.3 RAG vs 微调

| 维度 | RAG | 微调 |
|------|-----|------|
| 知识更新 | 实时（改知识库即可） | 需重新训练 |
| 成本 | 低 | 高 |
| 可溯源 | ✅ 能给出来源 | ❌ 难溯源 |
| 适用 | 知识频繁变化 | 固定能力/风格 |

## 2. RAG 完整流程

### 2.1 两个阶段

```
【离线阶段：构建索引】
文档 → 清洗 → 分块(Chunking) → 向量化(Embedding) → 存入向量库

【在线阶段：检索生成】
问题 → 向量化 → 相似度检索 → 重排(Rerank) → 拼接上下文 → LLM生成
```

### 2.2 架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                          RAG Pipeline                          │
├─────────────────────────────────────────────────────────────────┤
│  离线索引构建:                                                  │
│   文档 → 分块 → Embedding模型 → [向量数据库]                    │
│                                                                │
│  在线检索生成:                                                  │
│   问题 → Embedding → 检索Top-K → Rerank → 上下文+问题 → LLM     │
│              │                                      │           │
│         [向量数据库] ─────────────────────────────────┘           │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 关键环节详解

### 3.1 文档分块（Chunking）

分块是 RAG 质量的关键，块太大噪声多，块太小丢上下文。

| 策略 | 说明 | 适用 |
|------|------|------|
| **固定长度** | 按字符/token切分 | 简单 |
| **按句子/段落** | 保持语义完整 | 通用 |
| **递归分块** | 按层级分隔符递归切 | 主流 |
| **语义分块** | 按语义边界切分 | 高质量 |
| **重叠分块** | 块间重叠保留上下文 | 防边界丢失 |

> 经验：chunk_size 通常 200-500 token，overlap 10-20%。

### 3.2 向量化（Embedding）

| Embedding模型 | 特点 |
|--------------|------|
| OpenAI text-embedding-3 | 效果好，需API |
| BGE / BGE-M3 | 开源，中文强 |
| M3E | 中文开源 |
| Sentence-Transformers | 轻量本地 |

### 3.3 检索（Retrieval）

| 检索方式 | 说明 |
|---------|------|
| **稠密检索** | 向量相似度（语义匹配） |
| **稀疏检索** | BM25/关键词（精确匹配） |
| **混合检索** | 稠密+稀疏融合（推荐） |

### 3.4 重排（Rerank）

检索召回 Top-K 后，用更精细的 Rerank 模型重新排序，提升精度：

- **Cross-Encoder**：问题和文档一起编码打分，比向量相似度准
- 常用模型：BGE-Reranker、Cohere Rerank

### 3.5 检索质量指标

| 指标 | 说明 |
|------|------|
| **Recall@K** | Top-K中包含正确答案的比例 |
| **Precision@K** | Top-K中相关文档的比例 |
| **MRR** | 平均倒数排名 |
| **NDCG** | 归一化折损累积增益 |

## 4. RAG 进阶技术

### 4.1 常见优化

| 技术 | 解决的问题 |
|------|-----------|
| **查询改写** | 问题表述不佳 → 改写/扩展查询 |
| **HyDE** | 用假设答案检索，提升召回 |
| **多路召回** | 多种检索方式融合 |
| **父子分块** | 小块检索、大块作上下文 |
| **元数据过滤** | 按标签/时间预筛选 |

### 4.2 Agentic RAG

将 RAG 与 Agent 结合，让 Agent 自主决定：
- 是否需要检索
- 检索什么、检索几次
- 是否需要多轮迭代检索

```
问题 → Agent判断 → [需要检索?] → 检索 → [信息够吗?] → 再检索/生成
```

### 4.3 GraphRAG

基于知识图谱的 RAG，适合需要多跳推理的复杂问题：
- 抽取实体关系构建图谱
- 检索时利用图结构做关联推理

## 5. 工程实践

### 5.1 RAG 常见问题与对策

| 问题 | 原因 | 对策 |
|------|------|------|
| 检索不到相关内容 | 分块/embedding差 | 优化分块、换模型 |
| 召回但答非所问 | 缺Rerank | 加Rerank |
| 答案有幻觉 | 上下文不足 | 提示词约束"基于上下文" |
| 知识过期 | 索引未更新 | 定期重建索引 |

### 5.2 关键工程点

- **索引更新**：增量更新 vs 全量重建
- **分块调优**：根据文档类型调整策略
- **混合检索**：稠密+稀疏通常优于单一
- **引用溯源**：返回来源供验证
- **评估闭环**：用黄金数据集持续评估（结合L8-03/04）

### 5.3 与其他模块关系

- **L8-01 记忆**：长期记忆检索本质是 RAG
- **L6-03 语义缓存**：RAG 结果可缓存降本
- **L8-04 评估**：RAG 质量需系统评估

---

## 6. 总结

RAG 是让大模型"用上外部/私有/最新知识"的核心技术：
- 两阶段：离线建索引 + 在线检索生成
- 关键环节：分块、向量化、检索、重排
- 进阶：查询改写、HyDE、Agentic RAG、GraphRAG
- 工程核心：分块质量、混合检索、Rerank、引用溯源
- 相比微调，RAG 知识更新快、可溯源、成本低
