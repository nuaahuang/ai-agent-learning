# L8-03: 数据集与黄金数据集构建（Dataset & Golden Dataset）

## 1. 核心概念

### 1.1 数据集的用途

在 Agent 开发中，数据集贯穿全流程：

| 用途 | 说明 |
|------|------|
| **训练/微调** | 训练模型（结合L7-01） |
| **评估测试** | 衡量Agent质量（结合L8-04） |
| **RAG知识库** | 检索的知识源（结合L8-02） |
| **回归测试** | 防止迭代中能力退化 |

### 1.2 什么是黄金数据集（Golden Dataset）

黄金数据集是**经过专家精心标注、质量极高、作为"标准答案"基准**的数据集：

- **高质量**：人工审核，准确无误
- **代表性**：覆盖核心场景和边界
- **稳定性**：作为评估基准长期固定
- **权威性**：争议case由专家裁定

> 黄金数据集是评估 Agent 的"标尺"，标尺不准，评估全错。

### 1.3 数据集分类

| 类型 | 用途 | 是否变动 |
|------|------|---------|
| **训练集** | 模型学习 | 可扩充 |
| **验证集** | 调参 | 相对固定 |
| **测试集** | 最终评估 | 固定 |
| **黄金集** | 基准评估 | 严格固定 |

## 2. 数据集构建流程

### 2.1 标准流程

```
① 需求定义 → ② 数据采集 → ③ 数据清洗 → ④ 数据标注 → ⑤ 质量校验 → ⑥ 版本管理
```

### 2.2 各环节要点

| 环节 | 要点 |
|------|------|
| **需求定义** | 明确任务、覆盖场景、数据规模 |
| **数据采集** | 真实日志、人工编写、大模型合成、公开数据集 |
| **数据清洗** | 去重、去噪、脱敏、格式统一 |
| **数据标注** | 制定标注规范、多人标注、一致性检查 |
| **质量校验** | 抽检、交叉验证、专家审核 |
| **版本管理** | 数据版本化、可追溯、可回滚 |

## 3. 数据采集方式

### 3.1 四种来源对比

| 来源 | 质量 | 成本 | 特点 |
|------|------|------|------|
| **真实日志** | 高（真实分布） | 中（需脱敏清洗） | 最贴近实际 |
| **人工编写** | 最高 | 高 | 质量可控 |
| **大模型合成** | 中 | 低 | 量大但需筛选 |
| **公开数据集** | 不一 | 低 | 通用但可能不匹配 |

### 3.2 大模型合成数据（蒸馏）

用强模型（如GPT-4）批量生成训练/评估数据：

```
种子样本 → Prompt引导GPT-4生成变体 → 多样性扩充 → 质量筛选 → 入库
```

注意事项：
- **多样性**：避免生成同质化数据
- **质量筛选**：合成数据需二次筛选
- **去偏**：注意强模型自身的偏见传递

## 4. 黄金数据集构建

### 4.1 黄金数据集的标准

| 标准 | 说明 |
|------|------|
| **准确性** | 答案经专家验证，无误 |
| **代表性** | 覆盖典型场景 + 边界 + 难例 |
| **多样性** | 不同难度、类型、长度 |
| **一致性** | 标注规范统一 |
| **规模适中** | 几百到几千条精品 > 海量噪声 |

### 4.2 构建步骤

```
① 场景梳理 → 列出所有需覆盖的场景和能力点
② 案例收集 → 真实难例 + 边界case + 典型case
③ 标准答案 → 专家编写/审核标准答案
④ 多人标注 → 多标注员独立标注
⑤ 一致性校验 → 计算标注一致性(Kappa系数)
⑥ 争议裁定 → 专家裁定分歧case
⑦ 定版冻结 → 固定版本作为基准
```

### 4.3 标注一致性

| 指标 | 说明 |
|------|------|
| **Cohen's Kappa** | 两标注员一致性 |
| **Fleiss' Kappa** | 多标注员一致性 |
| **一致率** | 标注相同的比例 |

> Kappa > 0.8 视为高度一致；< 0.6 需重新审视标注规范。

### 4.4 黄金数据集的结构（示例）

```json
{
  "id": "golden_001",
  "category": "工具调用",
  "difficulty": "hard",
  "input": "帮我查北京明天的天气并提醒我带伞",
  "expected_output": {
    "tools": ["get_weather", "set_reminder"],
    "reasoning": "需要先查天气，根据结果决定是否提醒"
  },
  "evaluation_criteria": ["工具选择正确", "调用顺序合理", "参数准确"],
  "annotator": "expert_01",
  "verified": true
}
```

## 5. 工程实践

### 5.1 数据集质量原则

| 原则 | 说明 |
|------|------|
| **质量 > 数量** | 1000条精品 > 10万条噪声 |
| **覆盖边界** | 难例和边界case最有价值 |
| **持续迭代** | 线上发现的bad case补充进集 |
| **防数据泄露** | 测试集严禁混入训练集 |

### 5.2 数据脱敏

数据集（尤其真实日志）常含隐私，需脱敏（结合L6-05护栏）：
- PII脱敏：手机号、身份证、姓名等
- 敏感信息：密钥、内部数据

### 5.3 版本管理

- **数据版本化**：每次变更记录版本（如 DVC 工具）
- **可追溯**：知道每条数据的来源和修改历史
- **可回滚**：数据问题能回退到稳定版本

### 5.4 Bad Case 闭环

```
线上运行 → 发现Bad Case → 分析归因 → 补充到数据集 → 重新评估/训练 → 上线
```

这是数据集持续优化的核心闭环。

---

## 6. 总结

数据集是 Agent 质量的基石：
- 贯穿训练、评估、RAG、回归测试全流程
- 黄金数据集是评估的"标尺"，需专家精标、严格固定
- 采集方式：真实日志、人工、合成、公开各有取舍
- 核心原则：质量>数量、覆盖边界、防泄露、持续迭代
- 配合 Bad Case 闭环实现数据集持续优化
