# L8-04: Agent 测评（Evaluation）

## 1. 核心概念

### 1.1 为什么 Agent 测评困难

传统软件有明确的对错，但 Agent 输出是**开放、多样、概率性**的，测评面临：

- **答案不唯一**：同一问题有多种正确表述
- **主观性强**：好坏难以量化
- **多步骤**：Agent 是多步流程，需评估中间过程
- **不确定性**：同一输入可能产生不同输出

### 1.2 测评的层次

| 层次 | 评估对象 | 示例 |
|------|---------|------|
| **组件级** | 单个能力 | 检索召回率、工具调用准确率 |
| **任务级** | 完成任务 | 任务成功率、步骤正确性 |
| **系统级** | 端到端 | 用户满意度、整体质量 |

---

## 2. 评估维度

### 2.1 Agent 评估的核心维度

| 维度 | 说明 | 指标 |
|------|------|------|
| **准确性** | 答案是否正确 | 准确率、F1 |
| **完整性** | 是否完整回答 | 覆盖率 |
| **相关性** | 是否切题 | 相关性评分 |
| **工具使用** | 工具调用是否恰当 | 工具准确率 |
| **推理质量** | 推理过程是否合理 | 步骤正确率 |
| **安全性** | 是否安全合规 | 违规率 |
| **效率** | 速度和成本 | 延迟、token消耗 |

### 2.2 RAG 专项评估（RAGAS 框架）

| 指标 | 说明 |
|------|------|
| **Faithfulness** | 答案是否忠于检索内容（防幻觉） |
| **Answer Relevance** | 答案与问题的相关性 |
| **Context Precision** | 检索内容的精确度 |
| **Context Recall** | 检索内容的召回率 |

---

## 3. 评估方法

### 3.1 三大评估方法对比

| 方法 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **规则/指标** | BLEU、ROUGE、精确匹配 | 客观、快、便宜 | 难评开放性输出 |
| **LLM-as-Judge** | 用强模型当裁判打分 | 灵活、接近人类 | 有偏见、成本 |
| **人工评估** | 人类专家评分 | 最准 | 慢、贵、难规模化 |

### 3.2 LLM-as-Judge（主流方法）

用强大的 LLM（如 GPT-4）作为裁判评估 Agent 输出：

```
评估Prompt: "请根据以下标准给回答打分(1-5):
  - 准确性: ...
  - 完整性: ...
  问题: {question}
  标准答案: {reference}
  待评答案: {answer}
  请打分并说明理由"
```

**注意事项**：
- **位置偏见**：倾向于第一个/较长的答案
- **自我偏好**：偏好自己生成的内容
- **缓解**：交换位置测试、明确评分标准、多次取平均

### 3.3 评估模式

| 模式 | 说明 |
|------|------|
| **Pointwise** | 单个答案独立打分 |
| **Pairwise** | 两个答案对比择优 |
| **Reference-based** | 对照标准答案评估 |
| **Reference-free** | 无标准答案，靠规则/裁判 |

---

## 4. Agent 特有的评估

### 4.1 多步骤轨迹评估（Trajectory）

Agent 是多步流程，不仅看最终答案，还要看**执行轨迹**：

| 评估点 | 说明 |
|--------|------|
| **工具选择** | 是否选对工具 |
| **调用顺序** | 步骤顺序是否合理 |
| **参数正确** | 工具参数是否准确 |
| **错误恢复** | 出错后能否纠正 |
| **效率** | 是否走了冗余步骤 |

### 4.2 评估方式

```
最终结果评估(Outcome): 只看最后答案对不对
过程轨迹评估(Trajectory): 看每一步是否合理
  - 完全匹配: 轨迹与黄金轨迹完全一致
  - 顺序无关: 关键步骤都做了即可
  - 关键步骤: 只看是否包含必要步骤
```

## 5. 评估工程实践

### 5.1 评估流程

```
① 准备黄金数据集(L8-03) → ② 运行Agent → ③ 收集输出 → ④ 多维评估 → ⑤ 汇总报告 → ⑥ 归因分析
```

### 5.2 主流评估框架

| 框架 | 特点 |
|------|------|
| **RAGAS** | RAG专项评估 |
| **DeepEval** | 单元测试式LLM评估 |
| **LangSmith** | LangChain生态，全链路追踪评估 |
| **OpenAI Evals** | OpenAI官方评估框架 |
| **promptfoo** | Prompt/模型对比测试 |

### 5.3 关键工程点

| 要点 | 说明 |
|------|------|
| **回归测试** | 每次迭代跑黄金集，防能力退化 |
| **A/B对比** | 新旧版本对比，量化提升 |
| **持续评估** | CI/CD集成自动评估 |
| **Bad Case归因** | 失败case分析，补充数据集 |
| **多次采样** | 概率性输出，多次取平均 |

### 5.4 评估闭环

```
评估 → 发现问题 → 归因(数据/模型/Prompt/工具) → 优化 → 再评估
                                                    ↑__________|
```

## 6. 评估指标速查

| 场景 | 推荐指标 |
|------|---------|
| 分类任务 | Accuracy、Precision、Recall、F1 |
| 生成任务 | BLEU、ROUGE、BERTScore |
| 检索任务 | Recall@K、MRR、NDCG |
| RAG | Faithfulness、Context Precision/Recall |
| 工具调用 | 工具选择准确率、参数准确率 |
| 端到端 | 任务成功率、用户满意度 |

---

## 7. 总结

Agent 测评是保障质量、驱动迭代的关键：
- 难点：答案不唯一、主观性强、多步骤、不确定性
- 三大方法：规则指标（客观快）、LLM-as-Judge（灵活）、人工（最准）
- Agent 特有：除结果外还需评估执行轨迹
- 工程核心：黄金集回归、A/B对比、持续评估、Bad Case闭环
- 与 L8-03 数据集、L8-02 RAG 紧密配合，形成质量保障体系
